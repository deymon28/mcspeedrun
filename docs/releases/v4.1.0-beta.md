# Speedrun 4.1.0 beta (Minecraft 26.3)

A reliability release: runs now survive restarts and crashes, the timer measures real time, and
many gameplay, world-safety, and editor bugs are fixed. Existing configurations are upgraded
automatically; the only new setting is `settings.resume-after-restart` (on by default).

## New

- **Runs survive restarts and crashes.** The active run (timer, stage and task progress, found
  locations, splits) is saved to `run-state.yml` every 30 seconds and when the server stops. After
  the restart the run comes back paused and continues when the first player joins; the downtime
  is not counted. A saved run is only restored into the same world, game mode, and stage setup.
- **Crash-safe world cleanup.** Light beams and compass lodestones are recorded in
  `world-changes.yml`. If the server crashed while they existed, they are removed on the next
  start, so no beacons, iron blocks, end gateways, or lodestones remain in the world.
- `/run locate <x1> <z1> <yaw1> <x2> <z2> <yaw2>` estimates the stronghold from two throws noted
  from the F3 screen (the former six-coordinate form could never produce a result).

## Gameplay fixes

- The timer counted ticks, so it ran slow whenever the server lagged; it now measures real time.
- Killing an Ender Dragon while no run was active (before the start, after `/run stop`, or a
  respawned dragon after a finished run) announced a completed run.
- With "start when the first player joins", a finished or stopped run started over when a player
  rejoined an empty server. A new run now needs `/run start` or `/run reset`.
- Structures, portals, and task progress were registered while no run was active, including
  stage announcements and rewards after `/run stop`.
- `STRUCTURE_NETHER_PORTAL` tasks could never be completed.
- Stages without tasks completed instantly and announced meaningless splits; they are now skipped.
- The Wood task ignored cherry, mangrove, and pale oak logs.
- CUMULATIVE tracking counted only one item for a shift-click craft, counted dropped items again
  when they were picked up, and counted pickups cancelled by other plugins.
- Advancements moved an exactly known fortress, bastion, or stronghold location to the position of
  every further player who earned them.
- `/run reload` during a run reset all progress; progress is now kept and changed stages apply to
  the next run.
- Records were stored under the game mode active at the end of a run; a run whose game mode
  changed underway is no longer stored. `/run skipstage` without an active stage no longer
  disqualifies the run.
- `settings.pause-when-empty` did not pause a run that started on an empty server.
- Reward console commands without `%player%` ran once per online player instead of once.
- The chat prefix was added to every scoreboard line, and long lines with hex colors broke their
  colors; scoreboards are now restored when the plugin is disabled.
- Stronghold triangulation accepted intersections behind the player, and Nether coordinates of
  negative positions were off by one.
- Respawning in CASUAL mode could duplicate the Navigation Compass (kept inventory, or picking up
  the dropped one), and so could choosing a far destination and dropping the compass meanwhile.

## World safety and performance

- Light beams and hidden lodestones could be blown up or pushed by pistons, dropping beacons and
  iron blocks; they are now protected against explosions and pistons.
- Overlapping light beams and lodestones that shared a block could leave permanent blocks behind.
  Restores now keep the full block data, and block entities such as chests are never replaced.
- Light beams loaded or generated chunks on the server thread, also every 10 seconds for markers
  far from all players; chunks are now loaded through the platform queue and distant markers are
  left alone. Beams are only placed in the Overworld (in the Nether they ended up on the roof),
  and the placement sound no longer repeats on every refresh.
- A hidden lodestone in an unloaded chunk blocked placing a new one (for example after lighting a
  second portal or dying again far away); it is now restored when its chunk loads.
- `/run stop` left queued chunk loads running and lodestones in the world.
- A failing asynchronous chunk load could permanently stall the chunk queue on Paper.
- Records are saved in the background; run logs no longer write a plain text line into the JSON
  log, close without blocking the server for seconds, and are closed even when logging was turned
  off during the run.

## Configuration and editor

- Invalid values in `config.yml` are now really replaced by their defaults at runtime (as the
  console report already claimed); an invalid tracking mode no longer breaks the timer.
- If an upgrade could not be saved (for example a read-only backup folder), the server now keeps
  using the existing settings instead of the built-in defaults.
- Applying a stage change in the editor during a run wiped the active stages.
- Changing the completed-task timeout and then a stage name lost the timeout change.
- Invalid numbers in the editor block saving and show a clear message.
- `/run webconfig restart` now picks up a changed port or bind address from `config.yml`.
- Every loopback bind address keeps the editor's DNS-rebinding protection; stalled connections can
  no longer exhaust the editor's threads.
- `casual.start-pre-scan.radius` is limited to 1024 blocks, the radius actually used.
- Lowercase choices written by hand are shown correctly in the editor; error messages are
  announced to screen readers.
