# Beta v3.5.4 for Minecraft 26.1.2

Maintenance checkpoint before the Minecraft 26.3 compatibility update.
The original 3.5.3 alpha source and binary remain available under tag `v3.5.3`.

## Changes

- Require administrator permission for removing shared structure locations.
- Preserve nested settings, custom tasks and rewards when the web editor patches configuration.
- Load each portal-search chunk once and scan immutable snapshots off the server thread.
- Ignore obsolete portal-search callbacks and cancel the Bukkit fallback timeout after completion.
- Stop printing web access credentials automatically at startup. Administrators can request a link with `/run webconfig`.
- Bound web request bodies and main-thread waits, reject API path suffixes, and close HTTP exchanges reliably.
- Update JSON-java to 20260719, which fixes [GHSA-ghc9-756g-vrcv](https://github.com/stleary/JSON-java/security/advisories/GHSA-ghc9-756g-vrcv).
- Include the Gradle 9.5.1 wrapper with a pinned distribution checksum.
- Add an isolated, loopback-only server smoke harness with graceful shutdown and no recursive cleanup of supplied directories.

## Installation and compatibility

Requires Java 25 or newer and Paper 26.1.2. Stop the server, back up the plugin
data folder, replace the previous Speedrun JAR, then restart. Existing gameplay
modes, settings, tasks and language files are retained.

This checkpoint does not claim Spigot, CraftBukkit, or Folia compatibility. The
subsequent major beta targets the newer Minecraft version and broader core support.

## Verification

- Clean Gradle build: 59 JUnit tests passed.
- Real Paper 26.1.2 build 69: NORMAL, CASUAL SAFE/BALANCED/AGGRESSIVE/LOCATE and HARDCORE startup.
- Every profile: unauthenticated web API rejection, static editor delivery and graceful plugin/server shutdown.
- These headless checks do not establish complete multiplayer gameplay correctness or loaded-server performance.

## Current limitations

Use **Save & Apply** for web configuration changes. Independent Save/Apply state
and deferred changes during an active run are being revised in the next major beta.
Keep the web listener on localhost; an access link grants administrative configuration
access, including configured reward commands. Use an SSH tunnel for remote administration.
